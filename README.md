# CodeRefactor (CodeDiagram)

**대용량 소스코드 의존성 시각화 및 AI 리팩토링 지원 솔루션.**
복잡한 코드를 일일이 읽지 않고도 전체 구조를 그래프 한 장으로 파악함.
로버트 C. 마틴 결합도 지표로 위험 파일을 진단하고, Claude AI 해설을 제공함.
설치 없이 웹 브라우저에서 동작함.

> 한성대학교 컴퓨터공학부 · 2026-2학기 기업연계 SW캡스톤디자인 (2026-09 ~ 2026-12)

## 한눈에 보기

| 항목 | 내용 |
| :--- | :--- |
| 입력 | GitHub/GitLab/Bitbucket HTTPS URL, 또는 로컬 폴더 경로 |
| 출력 | 파일 의존성 그래프 + `[진단]` 패널 + 코드 뷰어 |
| 진단 | 순환 참조 · 파일 결합도(Ca, Ce, I, CBO) · 비대 코드 |
| AI | 함수 해설 · 결합도 위험 파일 3줄 리팩토링 제안 |
| 지원 언어 | Python, C++, C#, Java, TypeScript, JavaScript, HTML, CSS |
| 실행 환경 | Node.js 22 (`web/.nvmrc`) |

## 5분 만에 실행하기

```bash
cd web
npm install          # tree-sitter 네이티브 빌드 포함 (C++ 컴파일러 필요)
cp .env.example .env # 선택. AI 기능을 쓰려면 ANTHROPIC_API_KEY 입력
npm start            # http://localhost:3000
```

- 포트 변경: `PORT=3001 npm start`
- AI 키가 없어도 분석·진단·코드 보기는 정상 동작함.
- 설정 항목 전체는 `web/.env.example` 주석 참고.
  - `LOCAL_ROOTS`: 로컬 경로 분석 허용 범위
  - `GIT_HOSTS`: clone 허용 Git 호스트 추가
  - `MAX_CONCURRENT_ANALYSES` 등: 동시 분석·대기열 제한

## 처음 사용자 온보딩 4단계

처음 접속했다면 아래 순서로 보면 됨.

1. **프로젝트 분석 실행**
   - 상단 입력창에 GitHub URL(또는 로컬 경로) 입력 → **`[분석]`**.
2. **가장 크고 붉은 노드부터 클릭**
   - 크기가 큰 노드 = 비대 파일.
   - 붉은 그라데이션 = 결합도 HAZARD. 빨간 테두리 = 순환 참조.
3. **시각 신호 읽기** → [그래프 읽는 법](#2-그래프-읽는-법) 참고.
4. **원인 추적**
   - 좌측 리본 **`[진단]`** → 항목 클릭 → 해당 소스로 이동.
   - 파일 상세 뷰에서 함수별 **AI 해설** 확인.

## 기능 상세 가이드

### 1. 프로젝트 분석하기

- 상단 입력창에 주소나 경로를 넣고 **`[분석]`** 또는 Enter.
  - 예: `https://github.com/pallets/flask`
- URL이면 서버가 저장소를 얕게(shallow) 복제함.
  같은 저장소를 다시 분석하면 복제본을 재사용함.
- 분석이 끝나면 입력창 옆에 **저장소 칩**(예: `pallets/flask`)이 표시됨.
- 비공개 저장소와 HTTPS가 아닌 주소는 지원하지 않음.
- 운영 모드(`NODE_ENV=production`)에서는 로컬 경로를 막고 Git URL만 받음.

### 2. 그래프 읽는 법

기본 화면은 **파일 뷰**.
원 하나가 파일 하나, 선 하나가 파일 간 참조를 뜻함.

| 표시 | 의미 | 연계 진단 탭 |
| :--- | :--- | :--- |
| 원 색 | 언어 구분 | - |
| 원 크기 | 줄 수·함수 수 비례 (16~64px) | `[비대 코드]` |
| 원 뒤 그라데이션 | 결합도 등급 (주황 `WARN` · 빨강 `HAZARD`) | `[파일 결합도]` |
| 빨간 테두리 | 순환 참조 고리에 포함된 파일 | `[순환 참조]` |
| 선 굵기 | 두 파일 사이 참조 개수 | - |

- 결합도 판정은 서버에서 한 번만 함.
  그래서 캔버스 표시와 `[진단]` 패널 목록이 항상 같음.
- 멀리 축소하면 파일 이름이 숨겨지고, 확대하면 서서히 나타남(시맨틱 줌).

### 3. 그래프 조작하기

| 동작 | 결과 |
| :--- | :--- |
| 마우스 휠 / 드래그 | 확대·축소 / 화면 이동 |
| 노드에 마우스 올리기 | 이웃 파일만 강조 + 주요 함수 3개 미리보기 |
| 노드 드래그 | 노드 이동. 주변 노드가 물리 효과로 따라 움직임 |
| 노드 클릭 | [로컬 그래프](#4-로컬-그래프) 진입 + 코드 뷰어에 함수 목록 |
| 노드 더블클릭 | [코드 카드](#10-코드-카드) 열기 |
| 노드 길게 누르기 | [파일 상세 뷰](#8-파일-상세-뷰) 진입 |
| 선에 마우스 올리기 | 참조 요약 툴팁 |
| 선 클릭 | [참조 위치 목록](#6-연결선-참조-위치-보기) |
| 빈 곳 클릭 | 강조 해제 · 전체 보기로 복귀 |

### 4. 로컬 그래프

- 파일 노드를 클릭하면 **그 파일과 바로 연결된 파일만** 남기고 확대함.
- 큰 프로젝트에서 한 파일의 주변 관계만 볼 때 사용함.
- 빈 곳 클릭 또는 `Esc` → 원래 전체 보기와 위치로 복귀.

### 5. 계층형 배치

- 캔버스 우측 상단 **`[계층형]`** 버튼.
- 켜면 호출 순서대로 층을 나눠 배치함.
  화면 비율에 맞춰 위→아래 또는 왼→오른쪽으로 정렬됨.
- 끄면 원래 물리 배치로 돌아감.
- 파일 뷰 전용. 켠 상태는 다른 뷰에 다녀와도 유지됨.

### 6. 연결선 참조 위치 보기

- 두 파일 사이 선을 클릭하면 **실제 참조 위치 목록**이 코드 뷰어에 뜸.
  - 호출한 함수 이름, 파일 경로, 줄 번호 표시.
- 목록 항목을 클릭하면 해당 줄로 이동함.

### 7. 파일 탐색기

- 좌측 리본 **`[파일]`** 버튼으로 열고 닫음.
- 폴더 구조와 파일별 함수 개수 배지를 보여 줌.

| 동작 | 결과 |
| :--- | :--- |
| 폴더 클릭 | 접기/펼치기. 그래프도 함께 갱신 |
| 파일 클릭 | 그래프에서 해당 노드로 이동·강조 |
| 파일 더블클릭 | [파일 상세 뷰](#8-파일-상세-뷰) 진입 |
| 파일 드래그 앤 드롭 | 탐색기 안에서 순서 변경 |

- 열림/닫힘 상태는 다음 접속 때도 유지됨.

### 8. 파일 상세 뷰

- 파일 하나의 **내부 구조**(클래스·함수)와 다른 파일과의 연결을 보여 줌.
- 들어가는 법: 탐색기에서 파일 더블클릭, 또는 노드 길게 누르기.
- 함수 노드 클릭 → 코드 뷰어에 코드 + [AI 해설](#12-ai-함수-해설).
- 파일·클래스 박스 더블클릭 → 접기/펼치기.
- 결합도 위험 파일은 박스 테두리 색으로 표시됨.
- 나가기: 상단 **`[뒤로가기]`** 또는 좌측 리본 **`[파일]`** 뷰 버튼.

### 9. 코드 뷰어

- 화면 오른쪽 패널. 노드·선·진단 항목을 클릭하면 열림.
- 파일을 고르면 위쪽에 **함수 목록**이 뜨고, 함수를 누르면 그 코드로 이동함.
- 언어별 문법 색상(highlight.js)을 적용함.
- 왼쪽 가장자리를 드래그해 너비 조절. 더블클릭하면 기본 너비로 복귀.
- 상단 **AI 해설** 영역은 접고 펼 수 있음.

### 10. 코드 카드

- 파일 노드를 **더블클릭**하면 캔버스 위에 떠 있는 카드가 열림.
- 여러 카드를 동시에 띄워 파일끼리 비교할 수 있음.
- 카드 기능:
  - 제목 옆 배지: 함수 개수
  - 왼쪽 함수 목록 클릭 → 해당 함수 코드 표시
  - **`[코드 보기]`**: 파일 전체 코드 ↔ 선택 함수 코드 전환
  - 헤더 드래그로 위치 이동, `×`로 닫기

### 11. 진단 패널

- 좌측 리본 **`[진단]`** 또는 하단 상태바의 경고 배지(⚠)로 열기.
- 세 개 탭으로 구성됨. 탭마다 문제 개수 배지가 붙음.

| 탭 | 보여 주는 것 |
| :--- | :--- |
| 순환 참조 | 서로 물고 물리는 파일 고리 목록 |
| 파일 결합도 | 파일별 Ca, Ce, I, CBO와 등급(HAZARD/WARN/SAFE/N/A) |
| 비대 코드 | 줄 수가 많은 파일, 함수가 너무 많은 클래스(God Class) |

- **검색창**: 파일명·함수명·메시지로 목록을 걸러 냄.
- **등급 필터 칩**(파일 결합도 탭): `전체` / `HAZARD` / `WARN` / ... 로 거르기.
  - HAZARD·WARN 그룹은 기본 펼침, SAFE·N/A는 기본 접힘.
- 항목 클릭 → 그래프에서 해당 노드 강조 + 코드 뷰어로 소스 열기.
- 결합도 위험 파일은 [AI 결합도 리팩토링 제안](#13-ai-결합도-리팩토링-제안)과 연결됨.

### 12. AI 함수 해설

- 파일 상세 뷰에서 함수를 클릭하면 코드 위에 **AI 해설**이 뜸.
- 같은 코드는 서버가 캐시해 다시 호출하지 않음.
- 서버에 Anthropic API 키가 있어야 동작함.
  - 개발 환경: `web/.env`의 `ANTHROPIC_API_KEY` 사용.
  - 키가 없으면 해설 대신 안내 메시지가 표시됨. 나머지 기능은 정상.
- 호출 횟수 제한이 있음(기본: IP당 분당 20회).

### 13. AI 결합도 리팩토링 제안

- 결합도 HAZARD/WARN 파일을 고르면 코드 뷰어 위에 **AI 결합도 리팩토링 제안** 카드가 뜸.
- **`[진단하기]`** 를 누르면 Claude가 **3단계 제안**(결합도 진단 → 분리 대상 → 리팩토링 방향)을 생성함.
- 한 번 받은 결과는 **`[다시 진단하기]`** 로 갱신 가능.
- 카드 머리 부분을 눌러 접고 펼 수 있음.

### 14. 검색

- 분석 후 상단에 검색창이 나타남. `Ctrl+F`(Mac: `Cmd+F`)로 바로 이동.
- 입력하는 대로 일치하는 노드를 강조함.
- `Enter`: 첫 번째 결과로 화면 이동. `Esc`: 검색 해제.
- 진단 패널이 열려 있으면 `Ctrl+F`가 진단 검색창으로 감.

### 15. 범례와 상태바

- **범례**(캔버스 좌상단 `범례 ▸`): 이번 분석에 나온 언어 색상과 표시 의미.
  아래쪽 `단축키 보기`로 단축키 도움말을 열 수 있음.
- **상태바**(하단): 분석 결과 요약(파일·노드 수 등).
- **경고 배지(⚠ N)**: 분석 중 건너뛴 파일 등 경고 개수. 클릭하면 진단 패널이 열림.

### 16. 단축키

| 키 | 동작 |
| :--- | :--- |
| `Ctrl`+`F` | 검색 (진단 창이 열려 있으면 진단 검색) |
| `F` | 그래프 전체를 화면에 맞추기 |
| `Esc` | 열린 창 닫기 · 로컬 그래프에서 전체 보기로 |
| `?` | 단축키 도움말 열기/닫기 |

Tree-sitter 기반 파서로 아래 언어를 분석함.

| 언어 | 확장자 | 주요 추출 대상 |

## 왜 CodeRefactor인가

- **숲과 나무를 동시에** — 함수 단위 린트에 머물지 않고, 파일 간 의존 관계를 한 캔버스에서 조망함.
- **설치 없는 웹 접근** — IDE 플러그인이나 별도 서버 없이 브라우저에서 URL만 넣으면 동작함.
- **검증된 공학 지표** — $I$(불안정도)와 $CBO$(객체 간 결합도)로 위험 파일을 색으로 강조함.
- **진단에서 해설까지 한 화면** — 위험 파일 선택 시 Claude AI가 결합도 진단·분리 대상·리팩토링 방향을 3단계로 요약함.

### 2. 배경 및 문제 정의

소프트웨어 규모가 거대해질수록 파일과 클래스 간 복잡한 상호 참조로 인해 전체 구조 파악 및 유지보수 비용이 급증한다. 특히 현대의 AI 주도 개발(Vibe Coding) 확산으로 코드는 빠르게 대량 생성되지만, 아키텍처 검증은 여전히 수동에 머물러 있어 다음 문제가 반복된다.

| 문제 | 기존 환경 및 도구의 한계 | CodeRefactor의 해결 방식 |
| :--- | :--- | :--- |
| **인지 복잡도 과부하** | 수백 개 파일의 참조 관계를 파악하기 위해 텍스트 코드를 일일이 역추적 | **Compound 계층형 인터랙티브 캔버스**로 패키지-파일-클래스 관계를 시각화 |
| **기존 도구의 설치 장벽** | SonarQube, Sourcetrail 등은 무거운 서버 구축이나 복잡한 로컬 빌드 필수 | **Zero-Install 웹 브라우저 SaaS**로 URL 입력 즉시 빠른 렌더링 |
| **단편적 린트 vs 구조 조망 부재** | 단순 분기 복잡도나 스타일 린트만으로는 모듈 간 의존성 파악이 어려움 | **로버트 C. 마틴 공인 결합도($I, CBO$) 및 비대 코드 지표**로 거시적 위험도 진단 |
| **결함-코드 탐색 단절** | 진단 목록과 실제 소스코드 탐색이 분리되어 원인 파악에 시간 소요 | **진단 패널-캔버스 100% 동기화** 및 클릭 시 **소스코드·Claude AI 해설** 즉시 연동 |

### 4. 범위 (Scope)

- GitHub 원격 저장소 복제(Shallow Clone) 및 로컬 디렉토리 소스코드 수집 엔진
- Tree-sitter 기반 8개 언어(Java, Python, C++, C#, TypeScript, JavaScript, HTML, CSS) AST 구문 분석
- 외부 벤더·빌드 디렉터리(`node_modules`, `vendor`, `dist`, `build` 등) 격리 및 경로 샌드박스 보안 검증

- 순환 참조(Cycle) 탐지 및 비대 코드(비대 파일 · God Class) 정적 진단 엔진

- 사람 승인 없는 AI 코드 원격 저장소 강제 자동 푸시

### 8. 아키텍처 원칙 (Core Architectural Principles)

1. **Clean Layered Architecture** — Presentation(`web/public`), Application(`web/server`), External Cloud(Anthropic API) 계층을 분리하여 모듈 간 결합도를 최소화한다.
2. **Deterministic Metric Over Intuition** — 주관적 추정을 배제하고 Robert C. Martin의 학술 표준 공식($C_a, C_e, I, CBO$)과 서버 단일 임계치(`couplingThresholds.js`, `sizeThresholds.js`)만을 캔버스·진단 판정의 기준으로 삼는다.
3. **Single Source of Truth (UI-Diagnostics Sync)** — 판정은 서버 파이프라인 한 곳에서만 수행하고, 캔버스(그라데이션/크기/테두리)와 `[진단]` 패널은 동일한 서버 결과를 렌더링한다.
4. **Sandbox Security** — 소스코드 열람 시 `realpath` 검증으로 상위 디렉토리(`..`) 접근을 차단하고, 경로 정책·파일 크기·API Rate Limit을 적용하여 서버 자원을 보호한다.

### 9. 제약사항 및 가정

#### 제약사항
- **로컬·컨테이너 기반 시연 운영:** 학생 캡스톤 프로젝트 환경에 따라 파싱·그래프 연산은 로컬 또는 Docker 컨테이너(`web/Dockerfile`)에서 수행하고 최종 발표는 간이 시연 URL로 제공하며, 24시간 상시 클라우드 호스팅은 차기 단계로 이관한다.
- **Node.js 런타임 호환성:** Tree-sitter C++ 네이티브 바인딩 의존성에 따라 Node.js LTS(v18~v22) 환경에서 구동한다.
- **인증 모듈 최소화:** 다중 사용자 API 키 충돌을 방지하기 위해 회원가입 및 개인 API 키 등록 UI를 제외하고 서버 환경변수(`.env`) 단일 API 키로 운영한다.

#### 가정
- 분석 대상 프로젝트는 Git으로 형상 관리되거나 로컬에 유효한 소스코드 디렉토리를 갖추고 있다.
- 브라우저는 WebGL 및 최신 ECMAScript 표준을 지원하는 최신 Chromium(Chrome, Edge) 기반이다.

## 아키텍처

### 분석 흐름

```
브라우저 (web/public, 번들러 없는 전역 스크립트)
   │  POST /api/analyze { source }
   ▼
서버 (web/server, Express)
   gitService      URL이면 shallow clone, 지원 확장자 파일 수집
   parser          언어별 tree-sitter 파서로 함수·호출·import·클래스 추출
   resolver        호출·상속·변수 참조 연결 (웹 언어는 webResolver)
   graphBuilder    Cytoscape 노드/엣지 생성
   metrics → diagnostics → refactoring   결합도 계산, 진단, 제안
   │
   ▼  nodes, edges, diagnostics, suggestions ... (JSON)
그래프 렌더링 + 진단 패널
```

## REST API 규격

| API | 용도 |
| :--- | :--- |
| `POST /api/analyze` | 분석 실행. 그래프 JSON 반환 |
| `GET /api/file?id=&path=` | 코드 보기용 원본. 분석 루트 밖 경로는 거부 |
| `POST /api/explain` | 함수 AI 해설 (캐시됨) |
| `POST /api/explain/coupling` | 결합도 위험 파일 3줄 리팩토링 제안 |
| `POST /api/refactor` | AI 리팩토링안 (화면은 보류 상태) |
| `POST /api/auth/login` · `/logout` · `GET /me` | API 키 세션 로그인 |

### `POST /api/analyze` 예시

```json
{ "source": "https://github.com/user/repo" }
```

- 응답 주요 항목: `analysisId`, `nodes`, `edges`, `inheritanceEdges`, `variableEdges`, `webEdges`, `diagnostics`, `suggestions`, `cycleEdgeIds`, `warnings`
- `analysisId`는 `GET /api/file`로 원본 코드를 읽을 때 사용함.
