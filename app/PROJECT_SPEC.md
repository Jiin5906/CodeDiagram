# 코드 다이어그램 — MVP 프로젝트 스펙

## 1. 프로젝트 개요

Git 저장소 주소를 입력하면 코드 내부의 파일·함수·변수 간 참조 관계를 계층형 그래프로
시각화하고, 함수를 클릭하면 AI가 해당 함수의 역할을 자연어로 설명해주는 도구.

목적은 대학교 산학협력프로젝트(캡스톤) 제출용 앱의 핵심 로직을 미리 검증하는 것.
이 스펙은 팀 제출용이 아니라, 개인이 Claude Code로 먼저 프로토타입을 만들어보기 위한
기술 스펙이다.

## 2. MVP 범위 (반드시 이 범위만 구현할 것)

**포함:**
1. 단일 언어(Python) 코드 파싱
2. 파일이 함수를 감싸는 계층형(compound) 그래프 시각화
3. 함수 간 참조(호출) 관계를 실선 화살표로 표시
4. 화살표 클릭 시 참조 위치(파일명, 줄 번호) 목록 표시
5. 함수 블록 클릭 시 AI가 생성한 함수 설명이 그 자리에서 펼쳐짐
6. 펼쳐진 설명 안에 "전체 코드 보기" 토글 버튼

**제외 (이번 MVP에는 넣지 않음, 이후 확장 기능):**
- 설계 진단 (SOLID 원칙 위반 감지, 결합도/복잡도 경고)
- 리팩토링 제안 및 분할 미리보기
- 다국어(Python 외) 지원
- 변수 참조 그래프 (함수 참조가 동작한 뒤 확장)
- Android 앱 패키징 (1차는 웹 프로토타입으로 검증, 이후 WebView로 감싸는 방식 고려)
- Private 저장소 OAuth 인증

## 3. 핵심 동작 흐름

1. 사용자가 분석할 Git 저장소 주소(또는 로컬 폴더 경로)를 입력
2. 백엔드가 저장소를 clone(또는 로컬 폴더를 그대로 사용)
3. tree-sitter로 모든 `.py` 파일을 파싱하여 함수/클래스 선언과 호출 표현식 추출
4. 추출한 정보로 계층형 그래프 데이터(JSON) 생성
5. 프론트엔드가 Cytoscape.js로 그래프를 렌더링
   - 최상위 노드: 파일 (접혀 있으면 파일 단위 참조 개수만 표시)
   - 파일을 펼치면 그 안의 함수 노드가 보임
6. 화살표 방향 규칙: `[호출하는 함수/파일] → [호출당하는 함수/파일]`
7. 화살표 클릭 → 참조 위치 팝업 (파일명, 줄 번호 목록)
8. 함수 블록 클릭 → 그 블록이 확장되며 AI 설명 표시 (최초 클릭 시에만 AI 호출, 이후 캐싱)
9. 확장된 블록 안 "전체 코드 보기" 클릭 시에만 원본 코드 노출

## 4. 데이터 모델

```json
{
  "nodes": [
    {
      "id": "A.py",
      "type": "file",
      "label": "A.py"
    },
    {
      "id": "A.py::funcA",
      "type": "function",
      "label": "funcA()",
      "parent": "A.py",
      "code": "def funcA():\n    ...",
      "comment": "# 이 함수는 ...",
      "startLine": 4,
      "endLine": 9
    }
  ],
  "edges": [
    {
      "id": "e1",
      "source": "B.py::funcA",
      "target": "A.py::funcA",
      "references": [
        { "file": "B.py", "line": 12, "callerFunction": "B.py::funcA" }
      ]
    }
  ]
}
```

- 노드 타입은 `file`, `function` 두 가지만 MVP에서 사용 (변수 노드는 확장 기능)
- 함수 노드는 반드시 `parent`(소속 파일)를 가져야 함 — Cytoscape compound node 구조에 필요
- 엣지는 여러 참조 위치(`references`)를 배열로 가질 수 있음 (같은 함수가 여러 줄에서 호출되는 경우)
- 파일 단위로 접었을 때는 자식 함수 간 엣지를 자동 집계해서 파일-파일 엣지 개수로 표시

## 5. 기술 스택

### 파싱
- **tree-sitter** + `tree-sitter-python` — 함수/클래스 선언, 호출 표현식(call expression),
  함수 위 주석(comment/docstring), 각 노드의 `start_point`/`end_point`(줄 번호) 추출
- 같은 이름 함수가 여러 파일에 있을 경우: 같은 파일 내 우선 매칭 → 없으면 import된 파일에서
  탐색하는 간단한 규칙만 적용 (완전한 심볼 해석은 MVP 범위 밖)

### 백엔드
- **Node.js + Express**
- Git 처리: `simple-git` 또는 `child_process`로 `git clone --depth 1`
- tree-sitter는 Node 바인딩(`tree-sitter`, `tree-sitter-python` npm 패키지) 사용
- 엔드포인트 예시:
  - `POST /api/analyze` — Git URL(또는 로컬 경로) 받아서 그래프 JSON 반환
  - `POST /api/explain` — 함수 코드 + 주석 + 참조 위치 받아서 Claude API로 설명 생성, 캐싱

### AI
- **Claude API (Anthropic)** — 함수 설명 생성
- 프롬프트에 포함할 것: 함수 코드 전체, 함수 위 주석, 소속 파일명, 호출되는 위치 목록
- 캐시 키: 함수 코드의 해시값 — 동일 코드면 재호출하지 않음

### 프론트엔드
- **Cytoscape.js** — compound node(파일이 함수를 감싸는 중첩 구조) 기본 지원
- **cytoscape-expand-collapse** 플러그인 — 파일 박스 접기/펼치기
- 엣지 클릭 이벤트 → 참조 위치 목록을 팝업으로 표시
- 함수 노드 클릭 → 노드 크기를 확장하고 그 안에 AI 설명 텍스트 렌더링 (HTML 오버레이 또는
  cytoscape 노드 라벨 확장 방식 중 구현하기 쉬운 쪽 선택)

### 저장
- MVP 단계에서는 **SQLite** 또는 인메모리 캐시로 충분 (분석 결과·AI 설명 캐싱용)

## 6. 화면 동작 예시 (참고용 설명)

- 초기 화면: 파일 박스들이 나란히 배치되고, 파일 간 참조 개수가 화살표 굵기 또는 라벨로 표시
- 파일 박스를 클릭하면 펼쳐지며 내부 함수 박스들이 보임
- 함수 간 화살표는 `[호출자] → [피호출자]` 방향
- 화살표 클릭 시: "N references" 팝업, 클릭하면 파일명·줄 번호 목록 표시 (VS Code의
  "Find Usages" 팝업과 유사한 형태)
- 함수 블록 클릭 시: 블록이 확장되며 AI가 생성한 설명 텍스트가 그 안에 나타남
  - 설명은 함수 코드 + 주석 + 호출 위치를 종합해서 생성
  - 확장된 블록을 다시 클릭하면 접힘
  - 확장된 블록 안에는 "전체 코드 보기" 버튼이 있고, 눌러야만 원본 코드 전체가 노출됨

## 7. 개발 순서 제안 (Claude Code로 진행 시)

1. 백엔드: tree-sitter로 단일 Python 파일 파싱 → 함수/호출 관계 JSON 출력 확인
2. 백엔드: 여러 파일 대상으로 확장, Git clone 로직 추가
3. 프론트엔드: 목업 JSON으로 Cytoscape.js 렌더링 (compound node + expand-collapse) 먼저 검증
4. 프론트엔드-백엔드 연결: 실제 분석 결과를 그래프로 렌더링
5. 화살표 클릭 → 참조 위치 팝업 구현
6. AI 설명 기능: `/api/explain` 엔드포인트 + 프론트 확장 인터랙션 연결 + 캐싱
7. 실제 오픈소스 소규모 Python 저장소로 전체 흐름 테스트

## 8. 확장 여지 (MVP 이후, 지금은 구현하지 않음)

- 설계 진단: fan-in/fan-out, 함수 줄 수, 순환 참조 등 룰 기반 지표를 먼저 계산해서 임계치
  넘는 경우만 AI에게 "왜 문제인지" 설명을 요청하는 방식
- 리팩토링 제안: AI가 자연어가 아니라 구조화된 JSON(`{newFunctions, newEdges}`)으로 분할안을
  생성하도록 하고, 그 JSON을 별도 미리보기 다이어그램으로 렌더링
- 변수 참조 그래프: 함수 참조와 동일한 방식으로 변수 노드/엣지 추가
- 다국어 지원: tree-sitter grammar 추가 (JS, Java 등)
- Android 앱: 이 웹 프로토타입을 WebView로 감싸고 Kotlin으로 UI 셸 제작
